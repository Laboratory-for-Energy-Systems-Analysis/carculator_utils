Inventory export with Brightpath
==================================

``carculator_utils`` uses `Brightpath <https://pypi.org/project/brightpath/1.0.0a6/>`_
for Brightway Excel, SimaPro CSV and openLCA JSON-LD serialization. The runtime
requirement is ``brightpath>=1.0.0a6,<1.1``; this integration uses its v1 API,
currently published as an alpha. The dependency includes ``bw2io``, XlsxWriter
and ``olca-schema``. Model and LCIA calculations still use bundled resources
without importing Brightpath or Brightway or accessing a Brightway project.

With a completed vehicle inventory::

   workbook = inventory.export_lci(
       software="brightway2", format="file", directory="exports"
   )
   simapro_csv = inventory.export_lci(
       software="simapro", format="file", directory="exports"
   )
   foreground_zip = inventory.export_lci(
       software="openlca", format="file", directory="exports"
   )

Exports require one retained ``value`` sample. Select the sample before
constructing the model and inventory, as shown in :doc:`usage`.

.. list-table:: Return values
   :header-rows: 1

   * - Software
     - ``format="file"``
     - ``format="string"``
     - ``format="bw2io"``
   * - ``brightway2``
     - Excel path
     - List of Excel bytes, even for one year
     - Unlinked ``LCIImporter``
   * - ``simapro``
     - CSV path
     - Decoded Latin-1 CSV text
     - Unsupported
   * - ``openlca``
     - JSON-LD ZIP path
     - ZIP bytes
     - Unsupported

Multiple years return a list in model-year order. Filenames include each year.
``string`` exports use temporary files internally and do not create the supplied
destination directory. The default remains ``software="brightway2", format="bw2io"``.
Exports operate on copies and preserve calculated impacts and functional units.

Responsibilities and background linking
---------------------------------------

Carculator constructs activities and exchanges from its matrices, normalizes the
functional unit, and supplies vehicle parameters, fuel recipes and electricity
provenance. Its existing ecoinvent 3.10-to-3.9 mapping remains in use. Supported
targets remain exactly ``3.9`` and ``3.10``, with cut-off technosphere and
version-matched biosphere contexts. Format conversion does not migrate the
background to another release or system model.

Brightpath normalizes canonical dictionaries and writes the software formats,
including product names, compartments, units, CSV escaping and JSON-LD entities.
Foreground suppliers reference their own year-specific database. External
technosphere suppliers remain unlinked for matching to the user's background;
they are not labelled as members of the foreground database.

Structural validation runs before serialization. It does not certify external
background links against a licensed database. Brightway importers still need
the usual matching and writing steps in the destination project. The
``brightway`` extra retains the tested legacy stack (``bw2io<0.9``,
``bw2data<4``, ``bw2calc<2``). Brightpath's own dependency also installs
``bw2io`` without this extra; the extra selects the legacy versions.

SimaPro compatibility changes
-----------------------------

CSV files now use Brightpath's SimaPro layout and Latin-1 encoding. Decode
downloaded text as Latin-1; save returned strings with that encoding. Line breaks
inside fields become SimaPro's DEL character (``\x7f``). Brightpath transliterates
characters unavailable in Latin-1, so arbitrary Unicode comments need not be
byte-identical to the source. File and string outputs use the same writer.

Product identifiers include reference product, geography and activity name,
including vehicle-specific supplier suffixes. Foreground categories use valid
SimaPro material, energy, transport or waste-treatment categories. Carculator
retains its foreground waste classification exceptions for refined waste cooking
oil and carbon-fibre production.

Activity-specific comments and sources take precedence over catalog metadata.
Brightpath renders sources as ``Source: ...``. A missing or empty comment gets
``Inventory generated by carculator_utils.`` to meet its nonempty-comment
contract; missing sources do not acquire a citation.

The 24 custom octave/time/location noise flow identities cannot be represented
in SimaPro's standard flow sections. They were also absent from the previous
SimaPro output; omission now emits a warning. Other exchanges reported as
unrepresented by Brightpath fail export. Brightway and openLCA retain custom
noise names, quantities and compartments. Validation exempts only their known
compartments from Brightpath's standard compartment whitelist; malformed
quantities and unknown flow identities still fail.

openLCA scope
-------------

The ZIP contains foreground processes, their connected product flows and
elementary flows, units and locations. It does **not** contain the ecoinvent
background or LCIA methods. Brightpath has no packaged openLCA identifier catalog
for these ecoinvent targets. Generated external flows therefore need explicit
mapping to background providers and characterized elementary flows in the
destination database before calculation. Every openLCA export warns about this.
An importable ZIP alone does not establish equivalent LCIA results.

Verification
------------

``tests/test_export.py`` checks per-year return values for all formats and both
ecoinvent contexts, reads Excel with Brightpath/bw2io, inspects openLCA JSON-LD
provider links and signed quantities, and parses SimaPro products, waste inputs,
water-unit conversion and comments. Repeated real vehicle exports also check
scoped electricity suppliers and unchanged matrices and LCIA results. These
checks do not establish successful GUI imports or numerical equivalence inside
SimaPro or openLCA.
